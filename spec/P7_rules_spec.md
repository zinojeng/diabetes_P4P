# 糖尿病合併初期慢性腎臟病（P7 / DKD）品質支付收案規則規格書

- 文件用途：供資訊工程師依此規格實作 OS99（門診醫囑系統）P7 系列（P7001C／P7002C／P7003C）自動收案、批價、提示與鎖控邏輯。
- 涉及代碼：P4301C／P4302C／P4303C（初期慢性腎臟病，CKD）、P1407C／P1408C（P801）／P1409C／P1410C／P1411C（糖尿病，DM／P14）、P7001C／P7002C／P7003C（糖尿病合併初期慢性腎臟病，DM+CKD／P7）。
- 資料來源分組（依 group_key）：`p14_core`、`p7_core`、`p1407_auto`、`p8p9_limit`、`p14_schedule`、`lab_required`、`p7_interval`。所有數字與規則文字皆逐字取自來源 JSON，未自行換算或臆測；無法確認之處已列於第 (f) 節「待釐清事項」。
- 重要代碼命名提醒：**部分院內舊文件（`p1407_auto`、`p14_schedule` 之 2017 年版）以內部簡稱「P7」代表 P1407（新收案）**，與健保署 2023 年新增之「DKD 方案 P7（P7001C／P7002C）」為完全不同概念。本規格書所有「P7」一律指健保署 DKD 方案（P7001C/P7002C/P7003C），舊文件的「P7＝P1407」用法已於各節以【】註明，避免混淆。

## (a) 進入 P7 的前提條件：須先有 P4301（CKD）且已在 P14（DM）體系收案中

### 依據原文
1. **`p7_core` / DMCKD-ENROLL-1**：
   > 「於同院所同時由糖尿病及初期慢性腎臟病收案之病人，應於病人同一次就診中，完成糖尿病及初期慢性腎臟病追蹤管理照護。」
   → 此條文明確要求：申報 P7001C（DM+CKD 追蹤管理）之病人，必須是「同院所」已**同時**被 DM（P14 體系）與 CKD（P4301C 體系）收案中的病人，於同一次就診「合併完成」兩項照護，才產生 P7001C。這是本規格書判定「P7 收案前提＝P4301 + P14 收案中」的主要文字依據。

2. **`p14_schedule` / doc2-p70-doctor-eligibility**：
   > 「符合可帶入 P70 資格醫師：需同時具 DM 及初腎方案資格醫師（同時具人資員工趣味群組 PSEH → 大類別『t』→ 小類別『1』DM 及小類別『8』初腎的醫師）。P14 僅需 DM 資格，P70 則需 DM+初腎雙重資格。」
   → 醫師層級亦需同時具備 DM 與初腎（CKD）雙重資格，間接佐證病人層級也需同時具備兩個方案的收案身分，系統才會將 P70 排程判斷納入。

3. **`p7_core` / CKD-ENROLL-1、CKD-ENROLL-2**：P4301C（CKD 新收案）之收案條件為 CKD Stage1/2/3a（eGFR、UPCR 或糖尿病病人 UACR 門檻）且「收案前九十天內曾在該院所就醫，新收案當次需以『慢性腎臟疾病』為主診斷」。這是「先有 P4301」的具體收案動作定義。

4. **`p14_core` / stage2_entry_requirement**：DM（P14）體系須完整申報 P1407C 一次、P1408C 至少五次、P1409C 至少二次，才可進入第二階段（P1410C/P1411C）；此為「已在 P14 體系收案中」的原始定義依據（雖未直接對 P7 明文，但可作為「P14 收案中」狀態的判定基礎）。

### 規格結論（供實作）
- **前提條件 = 病人同時滿足：①已有 P4301C 收案紀錄（CKD 收案中，未結案）；②已有 P1407C 收案紀錄（DM／P14 收案中，未結案）。**
- 兩個條件皆成立後，**下一次回診**（同院所、同次就診）系統才可將該次就診判定為可申報 P7001C（追蹤）或 P7002C（年度評估，需另滿足次數門檻，見 (d)）。
- **⚠ 重要保留**：來源文件（`p14_schedule` system_logic_notes）明確指出：
  > 「P4301C…文件中僅提及其被計入 P7002(DKD 年度評估) 申報資格所需之『合計達三次以上』的其中一種代碼，未見『須先有 P4301 才能收案 P7』之明文規則。」
  → 也就是說，「必須先有 P4301 才能收案 P7」這句規則**是本規格書依 DMCKD-ENROLL-1（同時收案、同次完成）與醫師雙資格規則所做的合理推論，並非任一來源文件逐字寫出的明文規定**。實作前建議與健保署或院內個管單位再次書面確認，已列入 (f) 待釐清事項第 1 項。

## (b) P7 與 P801（P1408C）之間的間隔規則（含「10週改7週」異動與目前數值）

### P801（P1408C）本身的異動歷史（作為對照與沿革依據）
- **`p7_interval` / change-1-interval-update、effective-date**（來源文件：童綜合醫院系統異動申請單，申請單號 4430，申請日期 106.06.16，急件；依據全民健康保險署 **106.05.01** 更新之「醫療服務給付項目及支付標準」第八部第二章）：
  > 「P1407（C）與第一次 P1408（C）間隔時間規則變更：原規則為 10 週（70 天），更新為 7 週（49 天）。」
  - **異動前**：P1407C → 第一次 P1408C 間隔 ≥ 10 週（70 天）。
  - **異動後（106.05.01 生效）**：P1407C → 第一次 P1408C 間隔 ≥ **7 週（49 天）**。
  - 第二次起之 P1408C 每次間隔仍為 ≥ 10 週（70 天），每年度最多申報 3 次（`p14_core` / P1408C_interval_and_cap；`p7_interval` / p1408c-definition-interval-and-count）。

### P7（P7001C）與此規則的關係
- **`p7_core` / P7001-1**：
  > 「至少須間隔任一方案之新收案七週後才能申報 P7001C，每年度最多申報三次，每次間隔至少十週。」
  → P7001C 的「首次申報間隔」同樣採 **7 週**（與 P1408C 106.05.01 異動後之新規則數值一致），「新收案」在此指「任一方案之新收案」（即 P1407C 或 P4301C 兩者中較晚成立收案者，需再間隔 7 週）；後續每次（第 2、3 次）間隔仍為 **10 週**，每年度上限 **3 次**。
- **`p7_core` / P1408-2、P1410-1、P4302-2、P7001-4**（本次修正加註標記）：P1408C、P1410C、P7001C 三者「若當年度同時有申報，**合計**每年度最多申報三次」；P4302C 與 P7001C「合計最多申報三次」。
- **`p7_core` / P1408-4、P1410-2、P4302-3**：P1408C、P1410C、P4302C **不得與 P7001C 同時申報**（同一次就診不可重複申報疾病別追蹤費）。
- **`p14_schedule` / doc2-note1-mutual-exclusive**（健保署重申通知引用）：
  > 「追蹤碼(P1408、P1410 及 P7001；P4302 及 P7001)不得同時申報；若當年度同時有申報，合計每年最多申報三次。」

### 目前（現行）正確數值彙整
| 規則 | 現行數值 | 來源 |
|---|---|---|
| P1407C → 第一次 P1408C 間隔 | **≥7 週（49天）**（106.05.01 起生效，取代原10週/70天） | `p7_interval` change-1-interval-update, effective-date |
| P1408C 第2、3次間隔 | ≥10 週（70天） | `p14_core` P1408C_interval_and_cap；`p7_core` P1408-2 |
| P1408C 年度上限 | 3次（與P1410C、P7001C**合計**最多3次） | `p7_core` P1408-2 |
| 任一方案新收案 → P7001C 首次間隔 | **≥7 週** | `p7_core` P7001-1 |
| P7001C 第2、3次間隔 | ≥10 週 | `p7_core` P7001-1 |
| P7001C 年度上限 | 3次（與P1408C/P1410C合計、及與P4302C合計皆最多3次） | `p7_core` P7001-1, P7001-4 |
| P1408C 與 P7001C 同時申報 | **不可**（同次就診互斥） | `p7_core` P1408-4 |

### ⚠ 異動溯源限制
`p7_interval` 文件（106.06.16 申請）**內文只出現 P1407C/P1408C/P1409C/P1410C/P1411C**，並未出現 P7001C／P4301C 字樣；「10週改7週」的異動歷史文字紀錄僅存在於 P1407C→P1408C 的關係中。P7001C 之「七週」數值來自另一份較新文件（`p7_core`，標題「111-1修正規定」），其中**未附修正前舊文字對照**，故「P7001C 的 7 週規則是否也曾經歷『10週改7週』的異動、或自 P7 方案（2023年新增）上線時即為7週」**在來源文件中無法確認**，已列入 (f) 第 4 項。

## (c) 「P7 上次看診是否需要 OHA（口服降血糖藥）」規則異動

### ⚠ 命名衝突提醒（務必先讀）
使用者提問中的「P7」在不同來源文件中指涉不同代碼：
- 在 `p7_interval`（106.06.16 童綜合醫院申請單）與 `p1407_auto`／`p14_schedule`（2017年版）中，「P7」是**院內對 P1407C 的內部簡稱**（doc-meta-1：「研判院內慣用簡稱『P7』＝P1407C」）。
- 在 `p7_core`／`p14_schedule`（2023年版）中，「P7」則指健保署 DKD 方案（P7001C/P7002C/P7003C）。

以下 OHA 規則異動，來源文件明確對應的是 **P1407C（新收案）「上次看診」的用藥要求**，並非 P7001C：

### 異動內容
- **`p7_interval` / change-2-collection-rule**（106.05.01 生效，同一份 106.06.16 申請單）：
  > 「P1407（C）收案規則明定為『最近九十天曾在該院所診斷為糖尿病（ICD-10-CM前三碼為E08-E13）至少同院所就醫達二次(含)以上者，才可收案』，且**註明『第一次就診已未限制一定需開立藥物』**（即第一次看診不需開立 OHA/藥物即可計入就醫次數）。」
- 對照 2017／2023 年版 OS99 系統異動申請單（`p14_schedule` / doc1-p7-sc00-condition、doc2-p1407-eligibility）之**舊邏輯**：
  > 「…上次看診日 ICD-10 前三碼為糖尿病(E08.00~E13.99)、且**上次看診日 OS99 藥品欄位中有處方者**…」
  → 即異動前，判定「二次就醫」中較早一次（上次看診）**需**有開立糖尿病用藥處方；異動後（依 106.05.01 新規定），**第一次（較早一次）就診不再要求已開立藥物**，只需「同院所就醫達2次(含)以上」+「當次（最後一次）就診之同一處方 ICD10=E08-E13 且有開立 ATC前3碼=A10 之糖尿病用藥」即可（`p14_schedule` / doc1-p7-current-visit-condition、doc2-p1407-eligibility 中「當次」條件維持不變，僅「上次」條件放寬）。

### 對 P7001C／P7002C 是否適用
- 來源文件中**未見**針對 P7001C/P7002C「上次看診」是否需要 OHA 的獨立規則描述。`p7_core` 之 CKD-ENROLL-1/2、DMCKD-ENROLL-1 僅描述 CKD 收案的 eGFR/UPCR/UACR 檢驗條件與同次完成追蹤之要求，未提及用藥（OHA）作為 P7 收案或申報之判斷因子。
- 由於病人要進入 P7，前提已是 P1407C 收案中（依 (a) 節），而 P1407C 本身的「上次看診免 OHA」規則已內建於 P1407C 收案判定邏輯中，**理論上可合理推論此寬鬆規則會延續影響 P7 的收案母體**，但**沒有任何來源文件直接針對 P7001C/P7002C 重述或另訂 OHA 相關文字**。此點務必列為待確認事項（見 (f) 第 2 項），實作時不應自行假設 P7 對「上次看診」有獨立的 OHA 要求或豁免。

## (d) P7 申報前需完成的檢驗／前提條件

### P7001C（追蹤管理照護費，400點）
- **前提**：見 (a)(b)。當次就診**不得**另申報 P1408C、P1410C、P4302C（`p7_core` P7001-2）。
- **必要檢驗項目**（`p14_schedule` / doc2-p70-followup-req）：B.S（醫囑碼09005系列）、HbA1C 或 GA（09006 或 09139 二擇一）、LDL（0930 或 09044 或 09044CL）、血清肌酸酐 Cr（09015）、尿液微量白蛋白 UACR（0933，對應09016及12111）。
- **檢驗報告日期規範**（`p14_schedule` / doc2-table2-detail，依批碼分次要求不同）：
  - P700101（第1次）：B.S ≤40天、HbA1C或GA ≤40天。
  - P700102（第2次）：LDL ≤60天、Cr ≤60天。
  - P700103（第3次）：UACR(0933) ≤60天。
  - 整體 P70 系列報告日期規範上限為批碼日 0–60天內（doc2-p70-report-window）。
- **醫師資格**：需同時具 DM 及初腎（CKD）方案資格（doc2-p70-doctor-eligibility）。
- **團隊執行折算**：地區醫院及基層院所團隊醫事人員如為醫師加另一專業人員執行，申報點數為本項點數之 80%（`p7_core` P7001-3）。
- **年度上限**：3次，每次間隔≥10週（第1次為≥7週，見(b)）（`p7_core` P7001-1, P7001-4）。

### P7002C（年度評估管理照護費，800點）
- **前提**：`p7_core` P7002-1：
  > 「申報任一追蹤管理照護費後至少間隔十週才能申報 P7002C；本項限執行 P1407C、P1408C、P1410C、P4301C、P4302C 或 P7001C 合計達三次以上者始得申報，本項每年度最多申報一次。」
  → 累計次數採「跨 P14 系列 + P43 系列 + P7001C」共同計算，需系統跨代碼累加。
- **必要檢驗項目**（`p14_schedule` / doc2-p70-annual-req）：B.S、HbA1C或GA、SGPT、TG、CHO、LDL、HDL、Cr、Mic/Cr及U/R(二擇一)、NMRP（與 P1407C/P1409C 年度組合相同醫令碼）。
- **檢驗報告日期規範**（`p14_schedule` / doc2-table2-detail，P7002）：B.S≦40天、HbA1C或GA≦60天、空腹四項血脂≦40天、Cr≦60天、SGPT≦40天、UACR≦60天、眼底鏡檢或眼底攝影≦180天。
- **互斥規則**：P7002C **不得**與 P1409C 或 P1411C 同時申報（`p7_core` P7002-3；`p14_schedule` doc2-note2-annual-code：年度碼 P1409/P1411/P7002 每年只能擇一申報，限1次）。
- **團隊執行折算**：團隊執行時申報點數為本項點數之80%（`p7_core` P7002-2）。
- **年度上限**：1次（`p7_core` P7002-1；`p14_schedule` doc2-nhi-notice-p7002c）。

### P7003C（轉診照護獎勵費，200點，每人限申報一次）
- **前提**（`p7_core` P7003-1, P7003-2）：個案符合轉診條件（UPCR≥1000 mg/gm 或 eGFR<45 ml/min/1.73m²），並經轉診至「全民健康保險末期腎臟病前期(Pre-ESRD)病人照護與衛教計畫」院所，**確認該計畫收案後**方可申報；結案原因為恢復正常、長期失聯（≥180天）、拒絕再接受治療或死亡者，**不可**申報本項。
- **文件要求**：需填寫「全民健康保險轉診單」（附表8.2.8，一份留存院所），提供病患腎臟功能相關資料予被轉診機構；若為院內跨科轉診，須保留院內轉診單於病歷內，且於腎臟科收案追蹤後方予支付（`p7_core` SYS-6）。
- **互斥**：不得與 P4303C 同時申報（`p7_core` P4303-3）。

### 申報欄位（系統自動帶入邏輯，供OS99實作）
- P7001C、P7002C：門診案件分類填『E1』、特定治療項目代號(一)填『EK』（`p7_core` REPORT-3）。
- P4301C/P4302C/P4303C：案件分類『E1』、特定治療項目代號(一)『EB』（REPORT-2）。
- 申報方式：併當月份送核費用申報（REPORT-4）。

## (f) 待釐清事項清單

1. **「須先有 P4301 才能收案 P7」缺乏明文規則**：來源文件（`p14_schedule` system_logic_notes）明確指出「未見『須先有P4301才能收案P7』之明文規則」，本規格書 (a) 節之前提條件是依 DMCKD-ENROLL-1（同次就診完成合併追蹤）與醫師雙資格規則所做的合理推論，需與健保署或院內個管單位書面確認是否為強制前提，或僅為「同時收案者」的計費規則而非收案先後順序要求。

2. **P7001C／P7002C 是否適用「上次看診免 OHA」規則**：`p7_interval` 文件中「第一次就診已未限制一定需開立藥物」明確僅描述 P1407C 收案邏輯，未見任何來源文件對 P7001C/P7002C 之「上次看診」用藥要求另有明文規定或豁免。實作前需確認 P7 收案母體是否直接繼承 P1407C 的寬鬆規則，或需另訂。

3. **代碼命名衝突**：`p1407_auto`／`p14_schedule`(2017版)／`p7_interval` 文件中「P7」＝院內對 P1407C 之內部簡稱，與健保署 DKD 方案「P7（P7001C/P7002C/P7003C）」完全不同概念。所有相關系統文件、申請單、教育訓練資料建議統一正名，避免資訊室誤解需求範圍。

4. **P7001C「7週」規則的異動溯源不明**：目前僅能證實 P1407C→第一次P1408C 之間隔曾由 10週(70天) 改為 7週(49天)（106.05.01生效，`p7_interval`文件）。P7001C 的「任一方案新收案後7週」規則出自另一份標題「111-1修正規定」文件（`p7_core`），該文件未附修正前舊文字對照，故無法確認 P7001C 的7週規則是否也經歷過同樣的「10週改7週」異動、或自 P7 方案（2023年新增）上線時即為現行的7週數值，亦無法確認其生效日期。

5. **「下次排程」42天規則是否適用於 P70 系列**：`p14_schedule` system_logic_notes 指出，P14 系列「下次批碼」（系統提前提示應執行檢驗）之間隔為42天，此規則明確見於2017年版文件，但2023年版新增 P70 段落時「下次追蹤照護碼P700101-P700103定義」雖重述42天，P14段落本身之42天規則在2023年版未再次以數字明示，故 P14 下次排程之42天門檻是否仍延續、以及是否比照適用於P70系列的「下次排程」邏輯，文件未完全一致，需與資訊室確認目前系統實際採用之數值。

6. **進入P7體系後對P1408C/P1409C的鎖定期是否適用**：`p14_core` 通則十/`p7_core` P1408-5/P1409-4 明確規定「進入第二階段管理照護一年內不得再申報第一階段管理照護費 P1408C、P1409C」，此條文原始語境為 P14 第一→第二階段（P1410C/P1411C）之轉換；病人若因「同時進入P7體系」而觸發此鎖定，文件未逐字明示是否比照辦理，需確認。

7. **`p14_schedule`文件內部疑似筆誤**：2023年版文件「二、下次年度照護碼P7002定義」第1點寫「符合當日可執行P7002的病人(SC00檢驗進度預計照護碼為P140801-P1408103)」，其中「P140801-P1408103」根據上下文應為「P7002」相關代碼之誤植，但無法排除為原文既有誤字，實作前建議與原始文件提出單位核實。

8. **P1407C 收案排除就診記錄名單版本差異（178碼）**：2017年版排除「178、177、176、77、184」（5項，含178＝洗腎相關診別代碼之一），2023年版排除名單縮減為「177、176、77、184」（4項，移除178），文件未說明178代表何種就診類別及移除原因，此差異是否影響 P4301C/P7 收案母體判定亦需確認。

9. **P7002C 與 P7001C 間隔規則的「上次P碼」範圍**：`p7_core` P7002-1 僅寫「申報任一追蹤管理照護費後至少間隔十週」，未明確列舉此處「任一追蹤管理照護費」是否僅指 P1408C/P1410C/P4302C/P7001C，或亦包含 P1407C／P4301C 新收案本身作為起算點，實作時的起算基準日定義需再確認。

10. **P7003C／P4303C 之「Pre-ESRD計畫確認收案」介接方式**：文件僅說明需填寫「全民健康保險轉診單」並於腎臟科收案追蹤後方予支付，但未說明 OS99 系統應如何取得/驗證 Pre-ESRD 計畫端的「確認收案」狀態（人工回報或系統介接），此為關鍵的申報觸發依據，需與資訊室及腎臟科確認作業流程。
