# 糖尿病品質支付 P14 收案規則規格書（P1407 / P1408 / P1409）

- 文件用途：供資訊工程師依此規格實作「P14 糖尿病照護管理費」收案、批價間隔判斷、自動帶碼與品質獎勵計算之系統邏輯。
- 撰寫依據：多份健保署正式支付標準條文（含附表8.2.1~8.2.11）與童綜合醫院內部「OS99 系統異動申請單」（105~112年多個版本）之結構化擷取結果。
- 重要聲明：本規格書所有天數/週數/次數，一律**逐字保留原文件用語**（例如「七週」不強制換算為49天），並在換算處另註明換算值供工程師參考；凡文件間有衝突或未講清楚之處，一律列入第(e)節「待釐清事項」，不自行臆測補值。
- 版本判讀原則：`p14_core` 與 `p7_core` 兩組資料為健保署正式支付標準/附表全文（分屬不同年度版本，`p7_core` 標題含「111-1修正規定」，內容更新、更完整，且涵蓋 P14 與 P43/P70 系列之互斥/合計規則），視為**現行法規基準**；其餘各組（`p1407_auto`、`p8p9_limit`、`p14_schedule`、`lab_required`、`p7_interval`）為童綜合醫院內部系統異動申請單，反映「秘書/個管師的臨床需求」如何被轉譯為「OS99 系統參數」，可作為系統實作參考範例，但其中的院內限定代號（PSEH、SC00/SCOO、MO23）與部分天數（70天批碼間隔、42天下次排程提醒）**是否已同步最新法規**，需另行確認（見待釐清事項）。

## (a) P1407 / P1408 / P1409 收案條件、彼此關聯與時序關係

### A.1 P1407C — 第一階段新收案管理照護費（650點）

**收案對象條件（缺一不可）：**

1. 最近 **90天** 內曾在該院所診斷為糖尿病，ICD-10-CM 前三碼為 **E08–E13**。
2. 且同院所就醫達 **2次(含)以上**。
3. 當次收案須以**主診斷**（門診醫療費用點數申報格式點數清單段之國際疾病分類碼（一））收案。
4. 排除條件：
   - 同一院所經**結案**對象，**1年內**不得再收案（院所仍可依支付標準申報一般醫療費用）。
   - 經保險人 VPN 查詢，個案若已被其他院所收案照護中（**1年內仍有追蹤紀錄**），不得收案。
5. 收案前須向病人解釋本章目的、需配合定期回診，並發給文宣資料。

> 註：院內系統文件（`p7_interval`）提到 106.05.01 生效之規定版本中，「第一次就診已不限制一定需開立藥物」，即 90天內達成2次就醫的判定不要求第一次就診已開立糖尿病用藥。此細節**未見於** `p14_core` / `p7_core` 兩份較新法規全文，是否仍為現行規則需與健保署確認（見待釐清事項 Q3）。

**團隊資格前提（通則一）：**
- 醫師、護理衛教及營養衛教人員須經地方政府糖尿病共同照護網認證合格。
- 地區醫院/基層院所團隊可為「醫師+另一專業人員（護理師/營養師/藥師其一）」執行，惟團隊仍需取得地方政府三類人員認證。
- 醫事機構須向保險人分區業務組申報**同意**後才能申報本章費用。

### A.2 P1408C — 第一階段追蹤管理照護費（200點）

**時序規則（與 P1407C 及自身前次申報的關聯）：**
- 申報新收案（P1407C）後，**至少須間隔七週**才能申報第一次 P1408C。
- 每年度**最多申報3次**；第2次起，每次間隔**至少十週**。
- 若地區醫院/基層院所團隊由「醫師+另一專業人員」執行，申報點數為本項點數之 **80%**。
- （依 `p7_core` 111-1修正）若當年度同時申報 P1410C 或 P7001C，P1408C+P1410C(+P7001C) **合計最多3次**；P1408C 不得與 P7001C 同時申報。
- 進入第二階段照護後 **1年內不得再申報** P1408C（通則九/十）。

### A.3 P1409C — 第一階段年度評估管理照護費（800點）

**時序規則：**
- 申報追蹤管理照護費（P1408C）後，**至少間隔十週**才能申報。
- 本項限**執行 P1407C 及 P1408C 合計達3次(含)以上**者才得申報（`p7_core`修正後亦納入 P7001C 一併累計）。
- 每年度**最多申報1次**。
- 團隊「醫師+另一專業人員」執行時，點數為本項點數之 **80%**。
- 不得與 P7002C 同時申報。
- 進入第二階段照護後 **1年內不得再申報** P1409C。

### A.4 三代碼之間的整體時序關係（第一階段內）

```
P1407C(新收案，1次)
   │  間隔 ≥ 七週
   ▼
P1408C 第1次
   │  間隔 ≥ 十週
   ▼
P1408C 第2次（年度累計≤3次）
   │  間隔 ≥ 十週
   ▼
P1408C 第3次（年度累計≤3次，達上限）
   │  間隔 ≥ 十週，且 P1407C+P1408C 累計次數需 ≥ 3
   ▼
P1409C（年度評估，年度限1次）
```

### A.5 進入第二階段（P1410C/P1411C）之前提

- 個案須**完整申報**第一階段：P1407C 一次、P1408C **至少五次**、P1409C **至少兩次**（通常橫跨兩個以上年度）後，才能視病情需要進行衛教服務並申報第二階段照護項目。
- 第二階段照護醫師資格限內科/兒科/家醫科/新陳代謝/內分泌/心臟/腎臟專科醫師；非前述指定專科者需完成指定學會8小時課程並取得證明；第二階段醫師名單須經分區業務組同意；僅已參與第一階段照護之醫事機構可提供第二階段照護。
- P1410C（追蹤，100點，年度上限3次，每次間隔≥十週）、P1411C（年度評估，300點，年度上限1次，需P1408C+P1410C累計達3次以上，申報前需距最近一次追蹤照護費≥十週）。
- 進入第二階段後 **1年內不得再申報 P1408C、P1409C**（第一階段管理照護費），此為互斥鎖定規則，需系統依「個案首次申報第二階段照護之日期」判斷。

### A.6 結案與追蹤率停權

- **結案條件**：(1) 可歸因個案者，如失聯超過3個月、拒絕再接受治療；(2) 經醫師評估已可自行照護；(3) 個案未執行本章管理照護超過1年。
- **追蹤率停權**：申報本章費用之醫師，第一階段當季個案追蹤率 <20%（前一季已收案個案中本季完成追蹤者之比率），經輔導未改善，自保險人文到日之次月起 **1年內不得再申報**本章相關費用（P1407C~P1411C全部）。
- **登載不實罰則**：未依規定登錄或登載不實者，該筆管理照護費不予支付且不得再申報；HbA1C/LDL 任一檢驗值登載不實，取消當年度品質獎勵資格並追扣已核發點數；**連續2年**登載不實，自文到日次月起 **2年內不得再申報**本章費用。

### B.5 院內系統版（OS99）之檢驗窗口與報告齊全判定（僅見於院內文件，非健保正式條文）

- 2017年版：檢驗報告須於看診日 **≤40天內**齊全，才自動帶入照護碼；未齊全則先帶入排程「N」。

- 新增 GA（醣化白蛋白，醫令碼09139）可作為 HbA1C 之替代檢驗項目（2023年版起）；系統會將 GA 換算為 HbA1C 值代入，兩者同時填報則以填報值為主。

## (c) OS99 系統自動帶入/自動排程邏輯，及「秘書需求 → 資訊室系統邏輯」對應關係

### C.1 對應關係總覽

本規格書所整理的院內文件性質皆為「系統異動申請單」：由臨床端人員（個管師、糖尿病衛教護理師、秘書代號1798等）依健保署公告或院內會議決議，向資訊部提出**臨床/政策需求**，再由資訊部將需求轉譯為 **OS99（門診醫囑系統）** 之判斷參數與畫面邏輯。對應關係如下：

| 秘書/臨床端提出的需求（What） | 資訊室轉譯的系統邏輯（How） |
|---|---|
| 「病人常常沒有把檢驗做完，強制收案造成困擾」（106.05.23院長室決議） | 觸發方式由「強制立即帶入」改為「排程提醒N」，僅在報告齊全時才自動帶入正式照護碼 P1407 |
| 健保署106.05.01更新支付標準，P1407→第一次P1408間隔由10週改7週 | OS99的批碼判斷邏輯需同步調整最短間隔天數（是否已同步，見待釐清事項Q1） |
| 「同一次就診中應把糖尿病診斷排到主診斷」（109.07.02案例回饋） | 帶入P1407時，系統自動將含E08-E13之診斷移至病歷主診斷（第一順位） |
| 「醫師常忘記P1409一年只能報一次、P1408一年只能報三次，超額被核刪」（110.12.23行政會議決議） | 系統於開立P1409/P1408時查核SC00當年度累積次數，超過上限則**自動刪除本次資料**並彈窗提示已執行日期（P1409一年上限1次；P140801-03合計上限3次），屬**強制阻擋（hard block）**，非僅提醒 |
| 新增糖尿病初期腎臟病(DKD/P70)方案需與P14並行管理 | 新增P700101-03/P7002批碼邏輯，且新增「符合P70資格醫師」判定（需同時具DM+初腎方案雙重資格），與P14僅需DM資格區隔 |
| 「品管指標常常忘記做，導致品質獎勵沒有拿到」 | 新增以180天內未執行NMRP/HbA1c/Mic-Cr/血脂四項為條件，自動帶入未執行檢驗排程，且強制帶入後不可刪除/不可修改/不可輸入N |

### C.2 自動判斷 P1407 收案資格的系統邏輯（綜合多版本）

觸發時機：**2017年版**綁定於「OS99 → 醫師按ESC存檔時」；**2023年版**改為「OS99 → 於診療記錄畫面」即帶入（不再限定存檔動作）。

判斷條件（AND 關係）：
1. 看診醫師須為 PSEH 建檔醫師（人資員工趣味群組 PSEH → 大類別't' → 小類別'1' DM）。
2. SC00 中有核備日期，且本次掛號日與上次看診日間隔 ≤90天，該次上次就診之 ICD-10 前三碼為 E08.00~E13.99，且上次看診日 OS99 藥品欄位有處方紀錄。
3. 年齡 ≥18歲（2023年版起）。
4. 當次看診（同一處方）ICD10 為 E08-E13，且當次有開立糖尿病用藥（ATC前3碼 A10）。
5. 排除：取消掛號者；掛號日期一年內有洗腎室常用診別（178/177/176/77/184，2023年版起排除名單少了178變成177/176/77/184）就診紀錄者；SCOO生效中患者；SCOO糖尿病二階建檔患者；SCOO終止日與本次掛號日相隔 ≤364天者。

若上述條件皆符合，且必要檢驗報告齊全（≤40天內，眼底攝影≤180天）：系統於觸發時機自動帶入 P1407 照護碼，並將 E08-E13 診斷移至主診斷第一位。
若條件符合但報告未齊全：系統僅自動帶入必要檢驗項目之排程「N」，待報告齊全後才另行自動帶入 P1407 照護碼。

### C.3 P1408 / P1409 批碼鏈與次數上限的系統邏輯

- 院內系統文件所載「實際批碼（申報）間隔」為統一的 **70天** 鏈：P1407 → 間隔70天 → P140801 → 間隔70天 → P140802 → 間隔70天 → P140803 → 間隔70天 → P1409。此 70天（十週）邏輯**貫穿2017年版到2023年版皆未變動**，與健保法規現行文字「新收案後首次間隔七週（49天）、其後每次十週（70天）」**不完全一致**（見待釐清事項Q1）。
- 另有「下次排程強制提醒」邏輯，間隔為 **42天**（僅見於2017年版附件二，2023年版P70段落重述42天，P14段落未再明示）：即系統會在申報間隔尚未到期前，提前於42天後便帶出排程「N」提醒下次應執行的檢驗項目，此為「提示」而非「可申報」的門檻，與70天/七週的「可申報」門檻是兩套不同的天數，須避免混淆實作。
- P140803（第三次追蹤碼）與 P700103 帶入時，系統需額外判斷「當年度是否已批過年度碼（P1409/P1411/P7002）」，以決定下次排程給簡易套組（B.S、HbA1C）或完整年度套組。
- P1409（及P140801-03合計）之年度次數上限查核依據 **SC00** 資料表，統計「當年度1月1日起至當次就診日」之執行次數：
  - P1409 次數 >0 → 本次不可再開立，系統自動刪除本次資料，彈窗顯示既有執行日期。
  - P140801-03 合計次數 ≥3 → 本次不可再開立，系統自動刪除本次資料，依欲開立的是801/802/803分別彈窗列出三筆既有執行日期。
  - 開立P140803時，若當年度已有P1409紀錄，系統僅彈窗**提醒**（不阻擋），避免醫師重複排程下年度P1409檢驗。
- 開立 P14 系列醫令碼限 **PSEH 建檔醫師**（DM資格）；開立 P70 系列則需**同時**具備 DM 及初腎方案雙重資格。

### C.4 案件分類 / 特定治療項目代號（系統申報欄位自動帶入）

就診當次符合申報 P1407C/P1408C/P1409C/P1410C/P1411C 者：
- 門診：案件分類填 **『E1』**、特定治療項目代號（一）填 **『E4』**。
- 住院：給付類別填 **『C』**。

## (e) 待釐清事項（需與健保署或秘書/資訊室確認）

1. **【最高優先】P1407→P1408首次間隔「七週」是否已在 OS99 系統中生效？**
   `p14_core`／`p7_core`（判斷為較新之健保正式法規全文）明確載明「申報新收案後至少須間隔『七週』才能申報本項」；但院內系統文件（`p1407_auto`、`p14_schedule`）所載之「批碼（申報）間隔」，從2017年版到2023年版皆固定寫為 **70天（十週）** 一路貫穿 P1407→P140801→P140802→P140803→P1409，**未見任何版本將首次間隔改為49天（七週）**。僅有 `p7_interval` 這份106.06.16的申請單明確記錄「10週改7週」之異動內容與106.05.01生效日期。需向資訊室確認：現行 OS99 是否已真正套用49天（七週）作為P1407→第1次P1408的判斷門檻，或系統仍停留在70天判斷邏輯而尚未跟上法規修正（可能導致醫師實務上已達7週但系統仍卡到70天才允許申報，造成損失可申報件數的風險）。

2. **42天「下次排程提醒」與70天/七週「實際可申報」間隔的關係未完全交代。**
   2017年版附件二定義「下次批碼」門檻為42天，但文件未說明此42天是否僅是「提前跳出提醒」，或是否也曾被誤用為「可提前申報」的門檻。2023年版僅在P70段落重申42天，P14段落未重述，不確定P14是否仍沿用42天或已調整。需向秘書/資訊室確認此提醒間隔的目前设定值，並確認提醒間隔不會早於法定最短可申報間隔（避免系統提示醫師"可以看診"但實際上尚未達到可申報天數）。

3. **P1407第一次收案是否仍要求「第一次就診已開立藥物」？**
   `p7_interval`（106.06.16文件）記載106.05.01新規定「第一次就診已未限制一定需開立藥物」，但 `p14_core`/`p7_core` 兩份較完整法規全文之收案條件描述中未重複此細節（僅籠統寫「同院所就醫達2次以上」）。需確認此「第一次免開藥」的但書是否仍是現行有效規則，或已被後續法規版本取消/修改，避免院內系統的90天2次就醫判斷邏輯誤用已過時的但書。

4. **P1409C「年度限1次」與「第一階段完整收案需P1409達2次以上」的關係，需明確書面化避免混淆。**
   文件中「P1409C每年度最多申報一次」是指單一保險年度（曆年）內僅能申報1次；而「進入第二階段前需P1409C累計達2次(含)以上」則是指**跨年度累計總數**（通常至少橫跨2個年度）。建議系統資料模型明確區分「本年度已申報次數（count_per_year，用於阻擋超額申報）」與「終身/累計申報次數（用於判斷第二階段資格）」兩個獨立計數欄位，避免工程實作誤將兩者合併為同一計數器。

5. **P1407收案排除診別代碼清單版本不一致，原因未說明。**
   2017年版排除名單為「178、177、176、77、184」（5項）；2023年版變為「177、176、77、184」（4項，少了178）。文件未解釋178代表何種診別、為何被移除。需向資訊室或秘書確認178診別代碼之定義及移除178是否为有意的政策調整。

6. **GA（醣化白蛋白）可否替代HbA1C，是否有健保署正式依據？**
   `p14_schedule`（2023年院內文件）新增「HbA1C或GA(09139)二擇一」及「系統自動將GA換算為HbA1c代入」之邏輯，但健保署正式法規全文（`p14_core`/`p7_core`附表8.2.1~8.2.3）僅提及HbA1C(09006C)，未提及GA或其換算公式的正式授權依據。需確認此為院內自行擴充的替代方案，或健保署已有正式函釋支持，避免品質獎勵指標(HbA1C控制率)計算基礎不明確。

7. **P1408C/P1409C的「健保申報碼」與院內「醫令碼」之對應是否完整、無遺漏？**
   健保申報層級使用 P1408C／P1409C（單一代碼），院內系統則拆分為 P140801/P140802/P140803（對應P1408C的第1/2/3次）及 P1409（對應P1409C）。需與資訊室確認此對應規則在系統資料庫層級是否已建有明確的映射表，且P140801-03三者「合計」上限邏輯與健保法規「P1408C每年度最多3次」是否為同一件事（研判是，但文件未逐字明示兩套代碼系統为完全等價關係）。

8. **品質監測（強制檢驗排程，180天窗口）與P14收案狀態機之間的個案範圍是否完全重疊？**
   品質監測觸發條件僅要求「當次ICD10=E08-E13+開立A10藥物+180天內未執行4項檢驗」，並不要求「90天內同院所就醫≥2次」的收案門檻，理論上其觸發對象範圍可能大於（或不同於）P14實際收案個案範圍。需向秘書確認品質監測機制的目標族群是否刻意設計為「所有糖尿病用藥病人」（不論是否已被P14收案），或應與P14收案個案完全一致。

9. **`p14_core`原始檔案（108年版）未附任何修正前後對照或明確生效日期**，僅標題含「108年」字樣；而`p7_core`標題含「111-1修正規定」但同樣未附具體修正生效日期，僅以`<mark>`標記推測新增內容。若後續程式需要依「生效日期」判斷歷史申報案件應適用哪個版本的規則（例如70天vs49天門檻），目前手上文件**無法**提供精確的生效日期切點，需向健保署或資訊室索取正式函釋或版本異動公告的官方生效日期。

10. **P1410C/P1411C的完整支付規則（是否也有7週/十週的院內系統批碼版本、是否也受OS99強制阻擋邏輯管控）**，本次擷取的院內系統文件（`p1407_auto`、`p8p9_limit`、`p14_schedule`部分段落）多聚焦於P14第一階段（P1407/P1408/P1409），第二階段P1410C/P1411C的院內系統實作細節（觸發時機、批碼間隔、次數上限阻擋方式）記載較少，需另行向資訊室確認第二階段是否已有對等的系統自動判斷/阻擋邏輯，或仍仰賴人工判斷。

11. **P1408C/P1409C是否已同步納入P7001C/P4302C等跨方案合計計數（`p7_core`修正內容），院內OS99系統是否已實作跨代碼（P14+P43+P70）合計上限的查核邏輯？**
    `p7_core`（111-1修正）明確要求P1408C+P1410C+P7001C三者合計年度上限仍為3次，P1409C+P1411C+P7002C彼此互斥且需前置追蹤碼合計達3次以上；但院內系統文件中查核年度次數的邏輯（`p8p9_limit`所載SC00查核）僅描述P140801-03彼此合計，未見提及是否已納入P7001C等跨方案代碼一併計數。需向資訊室確認SC00查核邏輯是否已隨111-1修正同步更新為跨代碼合計，否則可能發生同一病人年度追蹤次數實際超標但系統未攔阻的情形。
